# D4

Рабочий стол Windows, собранный под вас: свой бар вместо панели задач, виджеты, темы, живые обои и мини-папки. Программа на C# + WPF (.NET 8) и сайт-визитка.

## Быстрый старт

| Файл | Что делает |
|---|---|
| `install-d4.bat` | Ставит .NET 8 SDK (через winget), собирает D4, создаёт ярлыки, предлагает автозапуск и запускает |
| `publish-github.bat` | Создаёт репозиторий на GitHub, включает сайт (GitHub Pages) и выкладывает `D4.exe` в Releases |
| `uninstall-d4.bat` | Удаляет программу, ярлыки и автозапуск |

Двойной щелчок по нужному файлу, дальше следуйте подсказкам в окне.

## Структура

```
d4/
├── app/        программа D4 (C# + WPF), подробности в app/README.md
├── docs/       сайт (GitHub Pages публикует эту папку)
├── scripts/    скрипты PowerShell для .bat-файлов
└── *.bat       запуск установки, выкладки и удаления
```

## Ручная сборка

```powershell
cd app
dotnet run -c Release
```

## Версия 1.8.0 — оптимизация

Приложение:
- частицы: градиентные кисти и перья кэшируются (раньше создавались каждый кадр), по одной матрице вместо трёх трансформаций на частицу, меньше точек в лентах сияния и волнах;
- анимация ставится на паузу при блокировке экрана (Win+L);
- список окон на баре кэширует пути к exe (меньше вызовов Win32 каждую секунду);
- сборка: ReadyToRun (быстрый запуск без прогрева JIT), TieredPGO, без фонового GC, без отладочных символов.

Сайт: ленивая отрисовка галереи, статичное зерно, меньше размытий и постоянных анимаций, `content-visibility` для секций ниже экрана.

### Почему не C++ / Rust / Go
Вычисления частиц занимают микросекунды; время уходит на отрисовку WPF и композицию окон в DWM, а это не зависит от языка симуляции. Нативная переписка потребовала бы отдельного рендера и межъязыкового моста, который невозможно проверить без Windows. Поэтому оставлен C#, где выжато всё, что реально влияет на нагрузку.
